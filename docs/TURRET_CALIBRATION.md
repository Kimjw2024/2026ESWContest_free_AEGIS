# Turret Kinematics, Calibration & Safety

## 1. Why Calibration Is Required

A pinhole 3D coordinate alone does not produce an accurate servo command. Real hardware contains:

- turret base position error
- pan/tilt zero offset
- pivot height and tilt-arm geometry
- laser optical offset
- base tilt and side lean
- camera depth-scale bias
- servo quantization, backlash and direction-dependent hysteresis

AEGIS separates the nominal kinematic model, measured calibration override and runtime direction compensation so that the same control code can be recalibrated after mechanical changes.

## 2. Inverse Kinematics

For a target expressed relative to the turret:

```text
pan = 90° − atan2(x_rel − dx_laser, z_rel − dz_laser) + pan_trim

dist_h  = horizontal distance to target
dist_PT = distance from pan/tilt pivot to target

tilt = 90°
       + atan2(y_rel, dist_h)
       − asin(l_arm / dist_PT)
       + tilt_trim
```

`axis_tilt` and `axis_lean` add pan-dependent correction to absorb front/back and left/right installation tilt.

## 3. Mechanical Parameters

| Parameter | Meaning |
|---|---|
| `pos_global` | turret pivot position in the global camera coordinate frame |
| `h_pivot` | pivot height |
| `l_arm` | tilt mechanism arm length |
| `dx_laser`, `dz_laser` | laser optical offset from mechanical axis |
| `pan_trim`, `tilt_trim` | zero-angle trim |
| `axis_tilt`, `axis_lean` | installation tilt/lean correction |
| `z_scale` | camera-depth scale correction used by prediction/control |

## 4. Latest Field Recalibration Procedure

The final integrated 2-RPi / 4CH rig was recalibrated with `calibration_turret.py` after the four-camera system and both turret axes were assembled and tested together.

The latest field procedure uses:

- **20 target positions for PT1**
- **20 target positions for PT2**
- multiple left/center/right and low/mid/high positions
- multiple depths rather than a single flat plane
- Fusion-provided 3D coordinates for every recorded target
- manual laser alignment for the measured pan/tilt command

Each sample stored in `calib_data.json` has the form:

```text
[[X, Y, Z], measured_pan, measured_tilt]
```

The calibration/debug target used for the latest run is a blue table-tennis ball. The HSV range in `config_turret.py` is:

```text
Target_1 lower = [100, 75, 60]
Target_1 upper = [125, 255, 255]
```

HSV is used for calibration because it provides a repeatable geometric target center independent of YOLO bounding-box center bias. YOLO remains the normal bird-detection path for the live application.

## 5. Interactive Calibration Sequence

`runtime/fusion_pc/calibration_turret.py` follows this sequence:

```text
Fusion provides stable 3D target
→ nominal IK computes initial PT1 angle
→ operator fine-adjusts laser to target and confirms
→ nominal IK computes initial PT2 angle
→ operator fine-adjusts laser to target and confirms
→ repeat across depth and image positions
→ optimize geometry + trim + axis correction + shared z_scale
→ save turret_calibration_overrides.json
→ verify both lasers on the recorded 3D targets
```

`turret_calibration_overrides.json` is physical-rig specific. After any camera/turret mechanical relocation, rerun the calibration and commit the regenerated override together with `calib_data.json`.

## 6. Runtime Direction Compensation

A separate field effect remained after static multi-point calibration: when the target moved **from top to bottom**, the physical tilt axis tended to stop slightly above the commanded target, while bottom-to-top motion was already accurate.

`6_turret_server.py` therefore applies direction-aware tilt backlash/hysteresis compensation after the normal inverse-kinematics calculation.

Current field-tuned control values:

| Item | PT1 | PT2 |
|---|---:|---:|
| downward tilt compensation | **0.80°** | **0.80°** |
| upward tilt compensation | 0.00° | 0.00° |

Additional control values:

| Item | Value |
|---|---:|
| direction epsilon | 0.18° |
| base EMA alpha | 0.40 |
| maximum adaptive alpha | 0.90 |
| pan deadband | 0.08° |
| tilt deadband | 0.10° |
| downward tilt response multiplier | 1.18 |
| maximum angle step | 18°/frame |
| servo minimum send interval | 0.020 s |
| laser keepalive | 0.10 s |

The downward correction is not a replacement for geometry calibration. It compensates a repeatable direction-dependent servo/mechanical behavior observed during the final integrated-rig test.

## 7. Current Runtime Override File

`runtime/fusion_pc/turret_calibration_overrides.json` is the authoritative numerical geometry/trim/depth-scale file for the physical rig.

Do not copy numeric values from an old report or development note into the runtime manually. The JSON generated by the most recent completed `calibration_turret.py` run is the source of truth.

The release checklist must therefore verify that these two files come from the same latest calibration session:

```text
runtime/fusion_pc/calib_data.json
runtime/fusion_pc/turret_calibration_overrides.json
```

## 8. Reported Historical Calibration Effect

The development report records an earlier PT1 mean-angle-error reduction after trim/axis optimization:

- Pan MAE: **35.0% reduction**
- Tilt MAE: **37.7% reduction**

These percentages are historical calibration-comparison evidence. They are not end-to-end 3D localization accuracy and should not be presented as the accuracy of the current 20-point field recalibration.

## 10. Predictive-Lead Version Note

The competition-deck verification snapshot records `system_delay = 0.14 s` and a previous predictive-lead experiment. The current release uses the conservative runtime preset:

```text
max_lead_dist = 0.0
command_lead_ratio = 0.0
```

Therefore forward predictive lead is disabled in the current demonstration preset until a new field timing calibration is completed.
